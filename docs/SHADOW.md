## Storage

Migration `20260928000700_soccer_model_shadow.sql`, applied 2026-09-28. Before applying, a rollback-only proof ran on production: all checks passed and fingerprint `35853ae2` was unchanged.

**`soccer_model_shadow_predictions`**
- One row per `(model_id, match_id)`.
- The issue trigger requires:
  - the row is born unsettled;
  - it is not future-dated;
  - it matches the canonical fixture, including kickoff;
  - the match is `scheduled`.
- The freeze trigger:
  - makes every prediction field immutable;
  - allows `home_score / away_score / outcome / settled_at` to be written **once**, only when the canonical match is `finished`, and only with the canonical score.
- No delete or truncate.
- Checks enforce:
  - probabilities sum to 1;
  - `input_as_of < predicted_at < kickoff_at`;
  - the outcome is consistent with the score.

**Other tables**
- `soccer_model_shadow_events`: append-only operational evidence (`started`, `issued`, `hold` with reason, `settled`, `missed`).
- `soccer_model_shadow_metrics`: append-only snapshot, one per settled count.

**Access**
- RLS is on for all three tables, with no policies.
- anon and authenticated privileges are revoked (anon PostgREST returns 401).
- Only the service role (soccer-ingest) touches them. soccer-api has no reference; a test scans soccer-api, soccer-news, the web source and the build.

## Runtime

soccer-ingest lane `model_shadow_bundesliga_dc`: it runs on every tick after the other lanes, throttles itself to hourly, and is not part of `/health ok`.

1. **Issue.** A scheduled Bundesliga league fixture kicking off within 7 days that has no row gets one prediction.
   - Inputs: finished Bundesliga league results that kicked off **strictly before `predicted_at`**, and so strictly before the fixture.
   - `input_as_of` = the latest input kickoff.
   - `input_hash` = sha256 of the exact input list. The list is archived write-once in R2 at `soccer-source/model_shadow_inputs/sha256/…`.
2. **Hold, never guess.** If any earlier league match that should have a result has none (live, stale or unscored), every fixture is held with reason `prior_result_unavailable`. Other hold reasons: `not_league_stage`, `insufficient_history`, `insert_rejected`. Each (match, reason) is recorded once as an event.
3. **Settle.** Rows whose canonical match is `finished` get the canonical score once. The prediction is never recomputed.
4. **Missed and late.**
   - Missed: a league match that kicks off after the shadow started without a row.
   - Late: an issue less than 24 h before kickoff.
5. **Metrics.** Written whenever the settled count changes. Each snapshot holds:
   - overall log loss, Brier, ECE and favourite accuracy;
   - home/draw/away calibration;
   - the Phase 1 train-frequency baseline (unchanged);
   - counts;
   - rolling 30/60/100 (complete windows only);
   - predicted vs observed rates by season and by month.

Drift is observational only. Rolling or adaptive calibration is a separate phase that needs approval.
